# Outfitly Atelier

Адаптивный интерфейс на HTML/CSS/JavaScript без фреймворка. Оформление использует
локальные изображения из предоставленного прототипа Atelier; вещи и образы
пользователя всегда загружаются из API. Демо-данных и локального хранилища сессии нет.

## Запуск

Для работы форм, фотографий и авторизации используйте единый HTTPS origin:

```powershell
npm run prepare:api --prefix src/frontend
dotnet run --project src/backend/Outfitly.Api --launch-profile https
```

Откройте `https://localhost:7043/`. После изменений повторите подготовку.
Настройка PostgreSQL, миграций и сертификата — в [разработке](../../docs/development.md).
`npm run dev` из этого каталога запускает просмотр оформления на 5173 без API;
регистрация и остальные серверные действия требуют запуска на 7043.

## Навигация и код

Страницы используют hash-маршруты: `/`, `/login`, `/register`, `/dashboard`,
`/wardrobe`, `/items/new`, `/items/{id}`, `/items/{id}/edit`, `/outfits`,
`/outfits/new`, `/outfits/{id}`, `/outfits/{id}/edit`, `/discover`, `/account`,
`/public/{items|outfits}/{id}`, `/shared/{items|outfits}/{token}`.
Например: `/#/wardrobe?category=Top&page=2`. Поиск выполняется по названию;
публичные подробности находятся в существующих списках, отдельного API для них нет.

- `src/main.js` — композиция, переходы, защита несохранённых форм и обработка сессии.
- `src/pages.js` — просмотр, каталоги, авторизация, публикация и диалог ссылок.
- `src/editors.js`, `src/save.js` — формы и последовательное сохранение.
- `src/components.js`, `src/ui.js`, `src/styles.css` — общие элементы и оформление.
- `src/api.js`, `src/auth.js`, `src/router.js` — HTTP, сессия и адреса страниц.

HTTP-контракты описаны только в [API README](../backend/Outfitly.Api/README.md).
Состав образа и фото сохраняются отдельными командами: интерфейс сохраняет ID после
создания, показывает частичный успех и не повторяет команды автоматически. После
конфликта нужно прочитать и сверить текущее состояние; выбранные поля и состав
остаются в редакторе. Добавление новых вещей предшествует исключению старых, чтобы
при замене состава временно не опустошать опубликованный образ.

## Проверки

Из этого каталога:

```powershell
npm test
npm run build
```

Порт 5173 должен быть свободен. Node-тесты проверяют HTTP-границу, CSRF, авторизацию,
фильтры, безопасный вывод данных и сохранение после частичного сбоя. Тестовые ответы
API не подтверждают работу PostgreSQL или браузерных cookie.

Для браузерной проверки используйте отдельную тестовую БД с миграциями и HTTPS:

1. Пройдите регистрацию, вход, выход и переход к личной странице после истечения сессии.
2. Создайте вещь, измените поля, загрузите JPEG/PNG, замените фото внешним URL и удалите его.
3. Проверьте поиск, категории, порядок и страницы каталога; пустой результат и ошибку сети.
4. Сохраните пустой образ, добавьте и исключите вещи, проверьте отображение коллажа.
5. Опубликуйте вещь и образ, откройте их как гость; создайте ссылку, откройте в другом
   браузере, отзовите её и убедитесь, что она недоступна.
6. Удалите вещь из образа и проверьте актуальный состав после перечитывания.
7. Прервите загрузку фото и сохранение состава: повтор не создаёт дубликат, данные
   формы остаются, после конфликта доступна сверка состояния.
8. На ширинах 360, 768 и 1440 проверьте все страницы, меню, отсутствие переполнения,
   порядок Tab, фокус диалогов, Escape и предупреждение о несохранённых изменениях.

Восстановление пароля, изменение профиля, социальные функции и свободный холст
образов не реализованы.
