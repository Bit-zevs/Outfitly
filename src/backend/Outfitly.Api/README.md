# Базовый HTTP API

API использует PostgreSQL через scoped `WardrobeService`, EF-репозиторий и
`IUnitOfWork`. Каждый успешный запрос изменения сохраняется одним вызовом
`SaveChangesAsync` до отправки ответа. Удаление вещи, изменение всех образов
и отзыв ссылок входят в одну транзакцию. При ошибке сохранения успешный ответ не выдаётся.

## Авторизация

Аутентификацию подключим отдельно. Сейчас схема `Pending` не авторизует запросы:
все личные эндпоинты отвечают `401`. Она не принимает идентификаторы из заголовков,
тела, query string или неподтверждённого bearer token.

Будущая схема должна выдавать authenticated identity с `ClaimTypes.NameIdentifier`,
содержащим непустой Guid существующего доменного пользователя. Отсутствующий/невалидный
идентификатор авторизованного пользователя даёт `403`. Подготовка доменного `User`
при регистрации/первом входе относится к следующему шагу аутентификации.
Схема тестовой аутентификации существует исключительно в тестовом проекте.
Контракт создания вещи/образа не содержит `OwnerId`; владельца задаёт сервер.

## Эндпоинты

В таблице `id` и `itemId` — Guid. Личные маршруты требуют авторизации.

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | `/health` | Проверка работы HTTP-приложения, без проверки БД |
| GET | `/api/wardrobe` | Публичные вещи, прежний маршрут сохранён |
| GET | `/api/wardrobe/outfits` | Публичные образы |
| GET | `/api/shared/items/{token}` | Вещь по активной ссылке |
| GET | `/api/shared/outfits/{token}` | Образ по активной ссылке |
| GET, POST | `/api/items` | Личный список / создание вещи |
| GET, PUT, DELETE | `/api/items/{id}` | Чтение / полное обновление / удаление своей вещи |
| PATCH | `/api/items/{id}/publication` | Публикация или снятие публикации |
| POST | `/api/items/{id}/share-links` | Создание ссылки на свою вещь |
| GET, POST | `/api/outfits` | Личный список / создание образа |
| GET, PUT, DELETE | `/api/outfits/{id}` | Чтение / обновление / удаление своего образа |
| POST, DELETE | `/api/outfits/{id}/items/{itemId}` | Добавление / удаление вещи из своего образа |
| PATCH | `/api/outfits/{id}/publication` | Публикация или снятие публикации |
| POST | `/api/outfits/{id}/share-links` | Создание ссылки на свой образ |
| DELETE | `/api/share-links/{id}` | Отзыв своей ссылки |

Отдельных маршрутов для справочника категорий, загрузки изображений, поиска,
социальных функций и пользовательских профилей нет. Фото пока задаётся URL.

Создание возвращает `201` и `Location`; остальные успешные команды — `204`.
GET возвращает `200`. Ссылка возвращает `{ "id", "token", "url" }`; `url` относительный,
ведёт к публичному чтению ресурса по токену. `id` используется для отзыва ссылки.
Просмотры вещей/образов не раскрывают токены. Пустой образ можно сохранить,
но нельзя опубликовать/расшарить. Повторное добавление одной вещи возвращает `409`.

### Тела запросов

Вещь, POST/PUT (name и category обязательны):

```json
{
  "name": "Рубашка",
  "category": "Top",
  "color": "White",
  "size": "M",
  "brand": null,
  "description": null,
  "photoUrl": "https://example.com/shirt.jpg"
}
```

Категории передаются строками: `Top`, `Bottom`, `Dress`, `Outerwear`, `Footwear`, `Accessory`.
Принимается ровно одно имя категории без окружающих пробелов, без учёта регистра.
Списки вроде `Top, Bottom`, числа, числовые строки и отсутствие category — `400`;
опущенные optional поля при PUT очищаются.

Образ, POST/PUT: `{ "name": "На каждый день", "description": null }`.
Публикация: `{ "isPublic": true }` или `{ "isPublic": false }`; флаг обязателен.
Создание ссылок и изменение состава образа не требуют тела.

Ошибки возвращаются в формате ProblemDetails:
`400` — невалидный JSON/данные; `401` — нет identity; `403` — чужой ресурс или невалидная
identity; `404` — нет ресурса/активной ссылки; `409` — запрещённый переход, дубликат
или конфликт конкурентных команд над образом. После конкурентного конфликта
перечитайте текущее состояние и повторите всю команду; сохранение откатывается целиком.
Неожиданные ошибки — `500` без внутренних деталей.

## Запуск

Задайте `ConnectionStrings__Outfitly` через окружение или .NET user secrets.
Пример формата без секретов: `Host=localhost;Port=5432;Database=outfitly;Username=outfitly`.
Сначала примените миграции по [инструкции Infrastructure](../Outfitly.Infrastructure/README.md).
API не создаёт БД и не применяет миграции автоматически.

```powershell
dotnet run --project src/backend/Outfitly.Api
dotnet test Outfitly.sln
```

HTTP-тесты запускают настоящее приложение через WebApplicationFactory и используют
изолированную SQLite БД. Проверяют HTTP-контракт, сохранение между запросами,
авторизацию, валидацию, публикацию/ссылки и согласованное удаление.
PostgreSQL-интеграционные тесты отдельно требуют `OUTFITLY_TEST_CONNECTION_STRING`.

Текущий синхронный контракт репозитория сохранён для небольшого объёма первой версии.
Асинхронные запросы с фильтрацией в БД и пагинацией — отдельное расширение Application.
